# 16. Тестирование и критерии приёмки

## Проверка форматов

- JSON Schema для Canonical и Human-Readable документов должна быть валидна, а соответствующий пример обязан проходить её проверку. Схемы и примеры хранятся в `docs/specification/schemas/`.
- В одном каталоге код символа уникален; отсутствующая или повторная идентичность должна давать диагностируемую ошибку.
- Расчёт `payload_hash` детерминирован для одинакового payload и включает геометрию, коннекторы и области.
- `lifecycle_status` принадлежит согласованному перечислению; все непроверенные записи имеют `draft`.

## Импорт и экспорт

- Проверяется цикл ASCII -> Canonical -> ASCII и IDF -> Canonical -> IDF для примитивов и коннекторов, поддерживаемых целевым форматом.
- Результаты Canonical для эквивалентных ASCII и IDF входов совпадают по коду, сегментам и коннекторам с допуском установленного округления.
- Повреждение одной записи не прекращает обработку остальных записей файла; ошибка указывает запись или строку и причину.
- В режиме `strict` неподдерживаемая геометрия вызывает ошибку экспорта; в режиме `compat` аппроксимация допустима только для явно поддерживаемых преобразований.
- Числовые коды legacy-атрибутов сохраняются при round-trip в IDF; преобразование в удобные словесные значения не теряет исходный код.

## Синхронизация

- Повторная синхронизация одного и того же релиза идемпотентна.
- Неизменённый локально официальный символ обновляется при наличии более новой upstream-версии.
- Локальный fork при изменении upstream получает `conflict` без автоматической перезаписи локального payload.
- Проверяются сценарии принятия upstream-версии, сохранения локальной версии и удаления символа из upstream без автоматического удаления локальных данных.
- Синхронизация не меняет `lifecycle_status` и не трактует `is_user_modified` как факт уже внесённой локальной правки.

## Проверка рефакторинга

- `GeometryCodec`, `CatalogSyncService` и presenter имеют отдельные unit/integration тесты на собственные контракты.
- Публичные фасадные методы сохраняются на переходный период.
- Smoke-тест запуска проверяет начальную загрузку приложения; полный набор интеграционных тестов проверяет импорт, экспорт, БД и конфликтные сценарии.
