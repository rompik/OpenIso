# 8. Модель данных и персистентность

Этот раздел задаёт атрибуты символа и текущую реляционную модель SQLite. Для реализации сверяйте `openiso/model/skey.py` (`SkeyData`) и преобразования в `openiso/controller/db.py`. В SQLite используются таблицы `skeys`, `geometry` и `symbol_sources`; массив `symbols` в Canonical JSON является структурой обменного документа, а не именем таблицы SQLite.

## 8.1 Атрибуты символа

Числовые коды перечислений являются стабильными значениями данных для хранения и обмена с IDF. Интерфейс показывает словесные названия, а при экспорте в IDF используется числовой код.

`OpenIso.json` является эталонным источником атрибутов символов. Локальная SQLite хранит их для работы приложения; `source_id` остаётся внутренним идентификатором связи с таблицей `symbol_sources` и в JSON не переносится.

| Название атрибута | Используется в `OpenIso.json` | Используется в SQLite | Описание атрибута |
| --- | --- | --- | --- |
| `name` | Да | Да (`skeys.name`) | Уникальный код SKEY; ключ записи в каталоге и идентификатор символа. |
| `group_key` | Да | Да (`skeys.skey_group_key`) | Ключ группы символа. |
| `subgroup_key` | Да | Да (`skeys.skey_subgroup_key`) | Ключ подгруппы символа. |
| `lifecycle_status` | Да | Да (`skeys.lifecycle_status`) | Стадия проектирования и готовности символа; значения и переходы определены в разделе 8.2. |
| `description_key` | Да | Да (`skeys.skey_description_key`) | Описание символа или ключ локализации описания. |
| `geometry` | Да | Да (таблица `geometry`) | Геометрия символа и точки присоединения. |
| `spindle_skey` | Да | Да (`skeys.spindle_skey`) | Код связанного шпинделя или пустое значение. |
| `orientation` | Да | Да (`skeys.orientation`) | Тип ориентации: симметричный (`0`), несимметричный (`1`), редуктор (`2`), фланец (`3`). |
| `draw_orientation` | Да | Да (`skeys.draw_orientation`) | Направление отрисовки: вдоль трубы (`0`), вертикально (`1`), по основным направлениям (`2`), пользовательское (`3`). |
| `flow_arrow` | Да | Да (`skeys.flow_arrow`) | Отображение стрелки потока: по умолчанию (`0`), выключено (`1`), включено (`2`). |
| `dimensioned` | Да | Да (`skeys.dimensioned`) | Размерность символа: по умолчанию (`0`), выключено (`1`), включено (`2`). |
| `tracing` | Да | Да (`skeys.tracing`) | Трассировка: по умолчанию (`0`), выключена (`1`), включена (`2`). |
| `insulation` | Да | Да (`skeys.insulation`) | Изоляция: по умолчанию (`0`), выключена (`1`), включена (`2`). |
| `flow_dependency` | Да | Да (`skeys.flow_dependency`) | Целочисленный код зависимости от направления потока; код `0` — значение по умолчанию. Словарь остальных кодов требует отдельного согласования. |
| `pcf_identification` | Да | Да (`skeys.pcf_identification`) | Идентификатор для обмена с PCF. |
| `idf_record` | Да | Да (`skeys.idf_record`) | Запись или идентификатор для обмена с IDF. |
| `user_definable` | Да | Да (`skeys.user_definable`) | Признак пользовательского определения символа согласно ISOGEN. |
| `isogen_standard` | Да | Да (`skeys.isogen_standard`) | Признак соответствия стандарту ISOGEN: нет (`0`), да (`1`). |
| `isogen_base_code` | Да | Да (`skeys.isogen_base_code`) | Базовый код ISOGEN; может быть пустым. |
| `source_id` | Нет | Да (`skeys.source_id`, внешний ключ) | Внутренний идентификатор записи `symbol_sources`; не переносится между JSON-каталогом и базами. |
| `source_name` | Да | Да (через `symbol_sources.name`) | Имя источника данных. |
| `source_type` | Да | Да (через `symbol_sources.source_type`) | Тип источника: `standard`, `company` или `project`. |
| `source_version` | Да | Да (через `symbol_sources.version`) | Версия источника. |
| `origin_type` | Да | Да (`skeys.origin_type`) | Происхождение записи: `user`, `official`, `forked_official` или `imported`. |
| `is_official` | Да | Да (`skeys.is_official`) | Тип владения символом: системный (`1`) или локально созданный пользователем (`0`). Системный символ нельзя изменять пользователю. |
| `is_user_modified` | Да | Да (`skeys.is_user_modified`) | Разрешение изменять символ пользователем по правилам ISOGEN: нет (`0`), да (`1`); не означает, что символ уже был изменён. |
| `upstream_symbol_code` | Да | Да (`skeys.upstream_symbol_code`) | Код соответствующего символа во внешнем каталоге. |
| `upstream_release_version` | Да | Да (`skeys.upstream_release_version`) | Версия выпуска внешнего каталога. |
| `upstream_symbol_version` | Да | Да (`skeys.upstream_symbol_version`) | Версия символа во внешнем каталоге. |
| `last_synced_upstream_version` | Да | Да (`skeys.last_synced_upstream_version`) | Последняя версия внешнего символа, применённая или обработанная локально. |
| `upstream_payload_hash` | Да | Да (`skeys.upstream_payload_hash`) | Контрольная сумма данных символа во внешнем каталоге. |
| `local_revision` | Да | Да (`skeys.local_revision`) | Номер локальной ревизии символа. |
| `sync_state` | Да | Да (`skeys.sync_state`) | Состояние синхронизации: `synced`, `conflict` или `upstream_newer`. |

## 8.2 Статус жизненного цикла символа

`lifecycle_status` описывает готовность конкретного символа к применению и хранится вместе с атрибутами символа в `OpenIso.json` и SQLite. Статус не заменяет и не выводится из `origin_type`, `is_official`, `is_user_modified` или `sync_state`: эти атрибуты описывают происхождение, владение, разрешение на пользовательское изменение и синхронизацию.

| Статус | Значение |
| --- | --- |
| `draft` | Черновик: символ создан, но проектирование ещё не начато или его данные неполны. |
| `in_progress` | Символ находится в разработке. |
| `in_review` | Разработка завершена; символ ожидает проверки. |
| `approved` | Символ проверен и разрешён к использованию. |
| `deprecated` | Ранее утверждённый символ выведен из применения или заменён другим. |

Все существующие записи эталонного каталога и каждый новый или импортированный символ получают статус `draft` и остаются в нём до ручной проверки конкретной записи. Статус `approved` назначается только после проверки уникальности кода, наличия группы и подгруппы, описания и корректной геометрии. В публикуемый официальный релиз включаются только утверждённые символы. Изменение происхождения или состояния синхронизации само по себе не меняет статус жизненного цикла.

Разрешены только следующие переходы:

| Исходный статус | Новый статус | Условие |
| --- | --- | --- |
| `draft` | `in_progress` | Начато проектирование. |
| `in_progress` | `in_review` | Разработка завершена и символ отправлен на проверку. |
| `in_review` | `approved` | Проверка пройдена и выполнены критерии утверждения. |
| `in_review` | `in_progress` | Проверка выявила замечания, требующие доработки. |
| `approved` | `in_progress` | Утверждённый символ явно возвращён в разработку для существенного изменения. |
| `approved` | `deprecated` | Символ заменён или выведен из применения. |

`deprecated` является конечным статусом; обратный переход в этой версии требований не предусмотрен. Переходы между статусами должны выполняться явно; редактирование полей происхождения и синхронизации не должно переводить символ в другой статус.

При переносе существующих записей, у которых статус отсутствует, статус не выводится автоматически из признака официальности или происхождения. До утверждения записи проходят проверку и остаются в `draft`. Шаблоны кодов и справочники групп/подгрупп не являются конкретными символами и не используют `lifecycle_status`; для них правила задаются отдельно, если они будут включены в модель данных.

## 8.3 Служебные атрибуты источника и синхронизации

Служебные атрибуты перечислены в общей таблице раздела 8.1. Они не являются визуальными или геометрическими свойствами символа и не показываются как часть его пользовательского описания. Их значения сохраняются при обычном редактировании символа.

## 8.4 Соответствие JSON и SQLite

- Ключ записи символа в `OpenIso.json` должен совпадать с кодом `name`; в SQLite код хранится в `skeys.name`.
- `group_key`, `subgroup_key` и `description_key` соответствуют колонкам `skey_group_key`, `skey_subgroup_key` и `skey_description_key`.
- `OpenIso.json` является эталонным источником атрибутов символов; локальная SQLite хранит используемое приложением представление этих атрибутов.
- `lifecycle_status` хранится отдельно от атрибутов происхождения и синхронизации и переносится между `OpenIso.json` и SQLite вместе с записью символа.
- Геометрия входит в запись `OpenIso.json` и хранится в SQLite отдельно, в таблице `geometry`.
- `source_name`, `source_type` и `source_version` в SQLite восстанавливаются через `source_id` и `symbol_sources`.
- `skeys.id` — внутренний первичный ключ SQLite, не переносимый атрибут символа.

## 8.5 Реляционная структура SQLite

Таблицы текущей модели и их назначение:

| Таблица | Назначение |
| --- | --- |
| `skeys` | Основные атрибуты символа и ссылки на группу, подгруппу, шпиндель и источник. |
| `geometry` | Геометрические элементы символа по транзакциям. |
| `transactions` | История создания и изменения символа. |
| `symbol_sources` | Нормализованный справочник источников символов и шпинделей. |
| `skey_groups`, `skey_subgroups` | Справочники групп и подгрупп. |
| `spindles` | Символы шпинделей, доступные как отдельные сущности. |
| `spindle_transactions`, `spindle_geometry` | История и геометрия шпинделей. |
| `catalog_symbols` | Снимки символов по релизам внешнего каталога для сравнения и разрешения конфликтов. |
| `app_metadata` | Служебные метаданные приложения, включая версию последней синхронизации. |

Связи между таблицами:

- `skey_groups` связана с `skey_subgroups`, `skeys` и `spindles` отношением один-ко-многим.
- `skey_subgroups` связана с `skeys` и `spindles` отношением один-ко-многим; пара ключей группы и подгруппы должна существовать в справочниках.
- `symbol_sources` связана с `skeys` и `spindles` отношением один-ко-многим; удаление источника обнуляет внешний ключ.
- `spindles` связана с `spindle_transactions` и `spindle_geometry`; `spindle_transactions` связана с `spindle_geometry`.
- `skeys` связана с `transactions` и `geometry`; каждый элемент геометрии ссылается также на транзакцию, в которой он записан.
- `skeys.spindle_skey` ссылается на `spindles.name` и может быть пустым.

Ограничения целостности и индексы:

- `skeys.name` и `spindles.name` уникальны.
- `skey_groups.skey_group_key` уникален; сочетание `skey_group_key` и `skey_subgroup_key` уникально в `skey_subgroups`.
- Источник уникален по сочетанию `name`, `source_type` и `version`.
- Значения `orientation` ограничены кодами `0..3`; `flow_arrow`, `dimensioned`, `tracing` и `insulation` — кодами `0..2`; `draw_orientation` — кодами `0..3`.
- Индексы истории: `idx_transactions_skey`, `idx_geometry_skey_txn`, `idx_spindle_geometry_spindle_txn`.

ER-описание этой текущей модели является нормативной частью данного раздела. Диаграмма Gaphor — визуальное представление той же структуры, а не отдельная схема данных.
