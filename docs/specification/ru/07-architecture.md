# 7. Архитектура и компоненты

## Исходные архитектурные ограничения

- OpenIso — десктопное приложение на Python с PyQt/PySide.
- Бизнес-логика и персистентность отделены от графического интерфейса; модули бизнес-логики и данных не импортируют GUI-фреймворки.
- Для SQLite используется стандартный модуль `sqlite3`; сторонний ORM не добавляется без отдельного согласования.
- Архитектурные изменения должны учитывать тесты и конфигурацию сборки, включая `pyproject.toml` и манифесты дистрибуции.

> Состояние остальных архитектурных требований: заготовка; уточнять по мере согласования целевого устройства приложения.

## Границы компонентов для рефакторинга

Рефакторинг выполняется поэтапно, без удаления действующих публичных методов и без изменения формата данных без отдельного согласования.

- `GeometryCodec` отвечает за разбор и сериализацию поддерживаемой строковой геометрии. Невалидный элемент возвращает диагностируемую ошибку, не прерывая UI-поток; поддерживаемые элементы должны проходить round-trip.
- `CatalogSyncService` отвечает за синхронизацию каталога и разрешение конфликтов. Он использует модель и персистентность, но не импортирует Qt; `SkeyService` сохраняет совместимые фасадные методы на время перехода.
- `MainWindowPresenter` координирует сценарии окна (`load`, `save`, `import`, `sync`) через интерфейс представления. Импорт GUI-фреймворка в бизнес-логику запрещён; диалоги и другие UI side effects остаются в окне.

Каждый компонент выделяется отдельной задачей с non-UI тестами. Полный перенос всех mixin и переписывание `SheetLayout` не является обязательной частью этого рефакторинга.
