# 15. Сборка, установка и распространение

## 15.1 Источники версии

- Единственный источник версии пакета — корневой файл `VERSION`.
- `pyproject.toml` получает версию проекта из `VERSION` через динамическую настройку setuptools.
- Windows-сборка включает версию из `VERSION` в метаданные приложения и имя EXE.
- Не меняйте `VERSION` при обычных изменениях в `develop`; обновление версии относится к подготовке выпуска.

## 15.2 Установка готового приложения

- Windows standalone EXE собирается PyInstaller и включает интерпретатор Python и зависимости. Пользователю не требуется отдельно устанавливать Python.
- Flatpak использует runtime и SDK, заданные в [манифесте](../../../packaging/flatpak/io.github.rompik.OpenIso.yml); установленному приложению не требуется Python на хосте.
- Наличие манифеста фиксирует конфигурацию сборки, но само по себе не подтверждает успешную сборку или публикацию Flatpak. До проверки сборки на Linux этот способ распространения не считается готовым пользовательским каналом.

## 15.3 Установка для разработки

Поддерживаемый README сценарий установки из исходного кода:

1. Клонировать репозиторий.
2. При необходимости создать и активировать виртуальное окружение Python.
3. Установить проект командой `pip install -e .`.
4. Запустить командой `python -m openiso`.

Для разработки и тестирования `pyproject.toml` предоставляет дополнительную группу зависимостей `dev`. В CI она устанавливается командой `pip install .[dev]`.

Для разработки и запуска из исходников требуется актуальная стабильная серия Python 3.15.x. Диапазон закреплён в `pyproject.toml`; обновления исправлений (например, 3.15.2) не требуют отдельной матрицы тестов.

## 15.4 Установка из PyPI

- Имя пакета — `openiso`.
- Публичный сценарий установки: `pip install --upgrade openiso`.
- После установки приложение запускается командой `openiso`; также поддерживается запуск `python -m openiso`.
- Для установки и запуска требуется актуальная стабильная серия Python 3.15.x согласно `pyproject.toml`.
- Основные зависимости пакета объявлены в `pyproject.toml`: PyQt6 и Markdown.

## 15.5 Сборка Python-пакета

- Пакет собирается стандартным Python build backend на основе setuptools.
- Команда сборки wheel и исходного архива: `python -m build`.
- Артефакты помещаются в каталог `dist/`.
- Метаданные собранных пакетов проверяются командой `twine check dist/*`.
- Конфигурация `pyproject.toml` включает в дистрибутив данные приложения, ресурсы, SQL/SQLite-файлы, документацию на английском языке и gettext-файлы.

GitHub Actions workflow `build-package-on-version.yml` собирает пакет при изменениях `VERSION` или `pyproject.toml` в `main` и по ручному запуску workflow. Собранные артефакты сохраняются как workflow artifact.

## 15.6 Проверки перед публикацией в PyPI

Workflow `publish.yml` выполняет следующую последовательность:

1. Запускает тесты на Linux.
2. Собирает wheel и исходный архив.
3. Проверяет метаданные пакетов через `twine check`.
4. Проверяет установку wheel на Windows и Ubuntu с одной актуальной серией Python 3.15.x и выполняет smoke-import пакета.
5. Публикует пакет только после успешных предыдущих задач: автоматически после публикации GitHub Release либо вручную при явном выборе `publish`.

Публикация использует GitHub Actions environment `pypi` и trusted publishing (`id-token: write`); учётные данные PyPI не должны храниться в исходном коде.

## 15.7 GitHub Releases

- Workflow `release-on-tag.yml` запускается для Git-тегов, начинающихся с `v`, либо вручную с указанным тегом.
- Версия для названия релиза получается из тега удалением начального `v`; ожидаемый формат тега показан в workflow, например `v0.8.5`.
- Если в `CHANGELOG.md` есть раздел для этой версии, его содержимое используется как release notes; иначе GitHub генерирует заметки автоматически.
- Публикация GitHub Release запускает workflow публикации пакета в PyPI после прохождения проверок.

## 15.8 Windows standalone-сборка

- Скрипт `build.ps1` собирает Windows-приложение с помощью PyInstaller и спецификации `OpenIso_win.spec`.
- Скрипт сборки выполняется с Python 3.15.x и устанавливает зависимости из `requirements.txt`. Это требование к среде сборки, а не к компьютеру пользователя.
- Временные каталоги `build/` и `dist/` предварительно удаляются скриптом, затем PyInstaller создаёт оконный EXE без консольного окна.
- В EXE включаются модули приложения, ресурсы `data/`, база/SQL-файлы, переводы и `VERSION`.
- Имя готового файла включает версию и дату сборки: `OpenIso-<версия>-<ГГГГММДД>.exe`.

Запускайте `build.ps1` только из рабочей копии, где удаление предыдущих `build/` и `dist/` не затронет нужные артефакты.

## 15.9 Требования к Python по сценариям

- **Пользователь Windows EXE:** Python отдельно не нужен; интерпретатор включается в сборку PyInstaller.
- **Пользователь Flatpak:** Python на хосте не нужен; среда приложения задаётся Flatpak runtime. Манифест пока не прошёл сборочную проверку.
- **Установка из исходников или PyPI:** требуется актуальная стабильная серия Python 3.15.x.
- **Разработка, CI и сборка Windows EXE:** используется одна и та же серия Python 3.15.x; старые серии не входят в матрицу тестирования.

## 15.10 Кроссплатформенные требования

- PyPI-пакет должен сохранять основной функционал на Windows и Linux.
- Сборка и установка должны использовать пути и команды, совместимые с соответствующей ОС.
- Windows standalone EXE и Linux Flatpak — отдельные способы распространения и не требуют установленного Python на целевой системе.
- Изменения файлов, включаемых в wheel или standalone-сборку, должны сопровождаться проверкой установленного/собранного артефакта, а не только запуском приложения из репозитория.

## 15.11 Открытые вопросы и расхождения

- При появлении новой стабильной серии Python следует обновить единственную поддерживаемую серию в `pyproject.toml`, CI, tox, сборочных сценариях и документации. Тестовые матрицы для прежних серий не добавляются.
- Добавлен Flatpak-манифест для runtime 24.08 и архитектур x86_64/aarch64. Его необходимо собрать и проверить на Linux перед заявлением о поддержке и публикацией; в текущей среде Windows инструменты Flatpak отсутствуют.
- PyPI-настройка `data-files` включает документацию из `docs/en/`, но не включает русские пользовательские руководства и `docs/specification/`. Решение о локалях документации в устанавливаемом пакете требует отдельного согласования.
- Не определены каналы публикации Windows EXE, правила подписи установочного файла и автоматизация его прикрепления к GitHub Release.
- Linux standalone-пакет и минимальные системные зависимости для графического интерфейса не специфицированы.
