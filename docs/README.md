## Структура

```text
docs/
├── README.md
├── ru/                 # Исходные пользовательские руководства и материалы для участников
├── en/                 # Английский перевод пользовательских руководств
├── specification/
│   ├── README.md       # Оглавление и правила ведения спецификации
│   ├── ru/             # Требования продукта, по одному файлу на пункт
│   └── schemas/        # JSON Schema и примеры форматов, описанных спецификацией
└── assets/             # Общие ресурсы документации
```

## Правила актуальности

- Изменения пользовательского поведения отражайте в спецификации и соответствующем руководстве.
- Сначала обновляйте русский оригинал; английский перевод можно отправить отдельным pull request.
- Сохраняйте в переводах технические идентификаторы, команды, имена полей и буквальные значения.
- Не привязывайте текущие руководства к версии программы, если шаги не отличаются между версиями. Для выпущенных состояний используйте Git-теги и [журнал изменений](../CHANGELOG.md).
- Проверяйте существование файлов и ссылок в языковых индексах после изменения структуры документации.
